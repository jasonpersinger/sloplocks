# Frontend Redesign: Picks-Focused UI

**Date:** 2026-03-20
**Status:** Approved

## Overview

Redesign `index.html` to focus exclusively on 5 daily picks per view. Remove all secondary content (ticker, slimegrinder, longslop, full slate, verbose logs). The new site is a clean pick card feed with cross-sport and per-sport views.

## What's Removed

- Top ticker bar (top edge %, total games, bot status)
- Slimegrinder Trio section
- Longslop section
- "View Full Slate" / collapsible slate button and full game list
- Verbose System Logs / Performance footer (expanded stats, season stats, methodology blurb, data sources links)

## Page Structure

Single-file `index.html`, no backend changes required.

```
[ SLOP LOCKS ]  [ Mar 20, 2026 ]
[ ALL ] [ NBA ] [ NCAAM ] [ MLB ] [ MMA ]
─────────────────────────────────────────
  Pick Card 1
  Pick Card 2
  Pick Card 3
  Pick Card 4
  Pick Card 5
─────────────────────────────────────────
  14-8 · 58.3% · ROI +12.4%
```

## Navigation

A pill row below the header: **ALL · NBA · NCAAM · MLB · MMA**. ALL is the default on load. Tapping a pill switches the feed without a page reload. Active pill is slime green (`#39FF14`); others are dim (`#555`).

**Implementation note:** The current HTML has four pills (NBA, NCAAM, MLB, MMA) and defaults to `loadSportData('nba')`. This redesign adds ALL as a new first pill and changes the default. The `currentSport` variable initializes to `'all'`, and the init call changes from `loadSportData('nba')` to `loadAllSports()`.

## Pick Selection Logic

### ALL tab (cross-sport)
1. Fetch all 4 sport `predictions.json` files in parallel using `Promise.allSettled`:
   - `data/nba/predictions.json`
   - `data/ncaam/predictions.json`
   - `data/mlb/predictions.json`
   - `data/mma/predictions.json`
2. For each successfully resolved fetch, extract its `slop_locks` array and tag each pick with its source sport key (e.g. `pick.sport = "nba"`).
3. Pool all tagged picks from successful fetches into one array.
4. Sort combined pool by `model_prob` descending.
5. Take top 5.

No pipeline changes needed — `slop_locks` already enforces positive edge (`edge >= 0`) and is computed daily by the pipeline.

### Per-sport tabs
Use that sport's `slop_locks` array directly. Already top 5 by `model_prob` with positive edge.

## `slop_locks` Item Schema

`slop_locks` items are **flat objects** (unlike the nested `matches` items which use `model_probs.home` and `edges.home.edge`). The pipeline's `_compute_slop_locks` function creates them directly with top-level fields:

```json
{
  "home_team": "Celtics",
  "away_team": "Knicks",
  "date": "2026-03-20",
  "matchday": null,
  "pick": "home",
  "model_prob": 0.6740,
  "implied_prob": 0.5830,
  "edge": 0.0910,
  "american_odds": -140,
  "decimal_odds": 1.714,
  "blurb": "Celtics rank 3rd in defensive efficiency..."
}
```

- `pick` is either `"home"` or `"away"`.
- The picked team is `home_team` when `pick === "home"`, else `away_team`.
- The opponent is the other team.
- `blurb` is a string generated by Claude Haiku. It may be an empty string `""` if the `ANTHROPIC_API_KEY` is not set — in that case, omit the blurb section from the card entirely.
- `sport` is **not** in the JSON — the frontend must tag each pick with its source sport key during the pool-building step in the ALL view (e.g. `pick.sport = "nba"`). Per-sport views can derive the sport from the tab being shown.

## Pick Card Design

Each card shows (in order, top to bottom):

1. **Sport badge + date** — `font-size: 9px`, dim (`#555`), uppercase. e.g. `NBA · MAR 20`. Sport label comes from the tagged `sport` key. Date is the pick's `date` field formatted as `MON DD`.
2. **Pick row** — flex row, space-between:
   - Left: picked team name (`font-size: 18px`, `font-weight: 700`, slime green `#39FF14`, uppercase)
   - Right: American odds (`font-size: 22px`, `font-weight: 700`, white `#fff`). Format: `+115` or `-140`.
3. **Opponent line** — `font-size: 12px`, dim `#888`. e.g. `vs KNICKS` (uppercase).
4. **Stats row** — three inline stats, `font-size: 10px`:
   - `Model: 67.4%` — slime green
   - `Market: 58.3%` — dim `#888`
   - `Edge: +9.1%` — slime green, always show `+` prefix
5. **Edge bar** — two-part bar showing market vs model visually. DOM structure:
   ```html
   <div class="edge-labels">
     <span>MARKET IMPLIED</span><span>MODEL EDGE</span>
   </div>
   <div class="edge-bar-outer">   <!-- full width, height:4px, background:#1a1a1a -->
     <div class="edge-bar-market" style="width:{implied_prob*100}%"></div>  <!-- background:#333 -->
     <div class="edge-bar-edge"   style="width:{edge*100}%"></div>          <!-- background:#39FF14 -->
   </div>
   ```
   The two inner divs are `display:inline-block` (or flex children) so they sit side by side. Together they span `model_prob * 100%` of the outer bar width, since `implied_prob + edge === model_prob` by definition.
   Label row above bar: `font-size: 9px`, dim `#555`, flex space-between.
6. **AI blurb** — only rendered if `blurb` is a non-empty string. `font-size: 10px`, color `#666`, `line-height: 1.5`. Separated from stats by `border-top: 1px dashed #1a1a1a`, `padding-top: 8px`, `margin-top: 8px`.

Card container: `background: #0d0d0d`, `border: 1px solid #1a1a1a`, `padding: 16px`. No slime-green background fill (the current "lock" highlight style is removed).

## Stats Footer

A single always-visible line pinned to the bottom of the container:

```
14-8 · 58.3% · ROI +12.4%
```

Style: centered, `font-size: 10px`, color `#555`, `padding: 12px`, `border-top: 1px solid #1a1a1a`.

**Data source:**
- `predictions.json` contains `pick_stats` with three sub-keys: `slop_lock`, `longslop`, and `all`. Use `pick_stats.all` (the aggregate across all pick types for that sport).
- `pick_stats.all` fields: `wins` (int), `losses` (int), `evaluated` (int), `hit_rate` (float or `null`), `roi` (float decimal or `null`, e.g. `0.124` = 12.4%).
- `hit_rate` and `roi` are `null` (not `0`) when `evaluated === 0`. Guard against null before calling `.toFixed()`.
- **Per-sport view**: use `pick_stats.all` from that sport's loaded JSON directly.
- **ALL view**: aggregate across all successfully loaded sports:
  - `total_wins = sum of each sport's pick_stats.all.wins`
  - `total_losses = sum of each sport's pick_stats.all.losses`
  - `total_evaluated = sum of each sport's pick_stats.all.evaluated`
  - `hit_rate = total_evaluated > 0 ? total_wins / total_evaluated : null`
  - Do **not** show ROI in the ALL view (cross-sport ROI requires raw bet data not available in the JSON) — show `--` for ROI.
- If `hit_rate` is null or `evaluated === 0`, show `-- · -- · ROI --`.
- Format: `{wins}-{losses} · {(hit_rate*100).toFixed(1)}% · ROI {roi >= 0 ? '+' : ''}{(roi*100).toFixed(1)}%`. Apply `+` prefix on ROI when positive.

## Header Date

The date in the header is populated from `new Date()` at page load time, formatted as `MMM DD, YYYY` (e.g. `Mar 20, 2026`). It does not depend on any JSON field.

## Loading State

While `Promise.allSettled` is in flight (ALL view) or a single fetch is in flight (per-sport view), show a centered `LOADING...` message with a pulse animation in the pick feed area. Render the cards only after all fetches settle (not progressively per sport). This keeps the layout stable.

## Error States

- If all sport fetches fail (ALL view): show `ERROR LOADING DATA` in the feed area.
- If a sport fetch fails in ALL view: skip that sport silently. Continue with picks from successful fetches.
- If all loaded sports have empty `slop_locks` (AND at least one fetch succeeded): show `NO PICKS TODAY — CHECK BACK AFTER 6AM UTC`.
- If a per-sport fetch fails: show `ERROR LOADING DATA`.
- If a per-sport `slop_locks` is empty: show `NO PICKS TODAY — CHECK BACK AFTER 6AM UTC`.

## Data Sources

All data comes from existing pipeline-generated JSON files:
- `data/{sport}/predictions.json` — contains `slop_locks`, `pick_stats`, `generated_at`

All fetch calls append `?t=Date.now()` as a cache-busting query string to avoid serving stale data, consistent with the existing approach in the current `index.html`.

**EPL exclusion:** A `data/epl/` directory exists in the repo but EPL is not an active sport in the pipeline config. Do not fetch `data/epl/predictions.json`. The four sports fetched in the ALL view are NBA, NCAAM, MLB, and MMA only.

No changes to pipeline, config, or any Python files.
